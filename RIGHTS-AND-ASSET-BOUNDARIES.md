# Rights, Licensing and Asset Boundaries

**Review date:** 2026-10-17  
**Status:** Production-readiness control; asset-level rights review remains open.

## 1. Purpose

This notice documents the intended separation between qFoldIT software licensing, third-party materials, trademarks, and visual assets used by the public site. It is not legal advice, does not replace a signed licence, and does not certify ownership of any particular file.

## 2. Repository licence and scope

The repository contains a root `LICENSE` with the GNU Affero General Public License, version 3. The root licence must be read together with explicit notices for files, directories, media, datasets, and third-party components.

For future releases, qFoldIT intends the AGPL grant to cover qFoldIT-owned software material that is expressly within that grant. The presence of an image, logo, name, publication, data source, external link, or trademark in this repository must **not** be treated as proof that qFoldIT owns it or can sublicense it.

**Historical-scope caution:** the root licence has appeared in prior public revisions without a comprehensive file-by-file media boundary. This notice does not purport to revoke or narrow any rights already granted to recipients under an earlier version. The exact scope of earlier grants and any required licence restructuring must be reviewed before making warranties to an investor, customer, or licensee.

## 3. Asset and third-party boundaries

| Material class | Intended treatment | Release control |
| --- | --- | --- |
| qFoldIT-authored software source | Governed by the applicable repository licence and file-level notices | Maintain copyright/provenance records; do not claim rights beyond the documented grant |
| qFoldIT-authored documentation and diagrams | License only under an explicitly documented content licence or the clearly applicable repository terms | Record author, source and licence scope |
| Illustrations, photographs, videos, generated artwork and other media | Rights are asset-specific; a public file path is not evidence of permission to commercialize or sublicense | Record creator, source, creation date, generation tool if applicable, input/reference rights, and permitted uses |
| External software, packages, SDKs and code snippets | Governed by upstream licences and notices | Keep dependency/SBOM and attribution records; do not replace upstream copyright lines |
| Scientific models, datasets, publications and structures | Governed by their source terms, research conditions and data licences | Record provenance, version, licence, attribution and permitted purpose |
| Trademarks, logos, characters and branded fictional worlds | No licence is granted merely because a name or image is referenced | Use only with a valid basis, appropriate nominative use, or written permission; obtain specialist review where necessary |
| Institutional and company names | References do not imply endorsement, partnership, employment, investment or licence | Require written evidence before describing a relationship as formal |

## 4. Publicly referenced visual assets requiring clearance

The public README currently references these asset paths:

- `assets/LEGO_HERO_POST.png`
- `assets/lego_qfoldit_hero.png`
- `assets/lego-standarts_toolbeth.png`
- `assets/lego_biotech.png`

The repository record available for this review does not contain a complete asset-by-asset rights dossier for these files. Their use of, or visual reference to, LEGO/Fortnite-style branding must not be described as an official relationship or licensed collaboration without documented authorization.

**Production gate:** before using these assets in paid promotion, investor materials, customer deliveries, app-store submissions, public-sector proposals, or as evidence of a licensed partnership, record the creator/provenance and rights basis or replace them with cleared original Foldnite artwork. A disclaimer alone does not establish permission to use protected artwork, characters, logos or trade dress.

This same rule applies to any future Disney, Warner Bros. Discovery, LEGO, Epic Games or other third-party entertainment assets.

## 5. Scientific and technology lineage

Names and links to Foldit, Baker Lab, University of Washington, Rosetta, OpenStructure, CAMEO, Epic Games, Fortnite/UEFN, Unity, UNIGINE, or other external projects are references to technologies, research, ecosystems or platforms. They do not, by themselves, establish an endorsement, partnership, assignment of intellectual property, right to redistribute upstream code, or permission to use trademarks.

Where source code is reused, the exact upstream repository, revision, applicable licence, attribution notice and any required source-disclosure obligations must be recorded. Research lineage and scientific inspiration must be distinguished from ownership of a method, paper, model, dataset, source file or trademark.

## 6. Minimum asset-register fields

Before a release or commercial use, add a row for each material asset with:

1. path and SHA-256;
2. creator/rightsholder and source URL or internal creation record;
3. creation/acquisition date and tool, if generated;
4. applicable licence or signed permission;
5. whether modification, commercial use, sublicensing and redistribution are permitted;
6. attribution requirements and expiry/territory restrictions;
7. approval owner and clearance date.

## 7. Release acceptance checklist

- [ ] No third-party logo, character, branded world, photograph, model or dataset is represented as owned or licensed without supporting evidence.
- [ ] Upstream licence and copyright notices are preserved.
- [ ] Public source code has an unambiguous licence scope.
- [ ] Media and documentation are covered by an explicit licence or excluded with clear asset-level notices.
- [ ] Third-party dependency and asset manifests are included in release materials.
- [ ] The marketing surface makes no unsupported claim of affiliation, endorsement, licensing or scientific validation.
- [ ] An IP/licensing reviewer has approved any dual-licence, commercial relicensing or strategic transaction package.
