INDUSTRIAL‑CAMEO Proxy — Private CAMEO Integration

How qFoldIT acts as a private prediction server for corporations
[ CAMEO Private Mode ]
(authorized under corporate token)
↓ weekly blind target (e.g. CIF‑file, protein sequence)
[ INDUSTRIAL‑CAMEO Proxy ]
  · authenticates as a private prediction server (OAuth2 / token handshake)
  · receives target, stores in secure queue
  · converts target to UAG → UEFN level via building_grid_mapper.py
↓
[ UEFN Island / Fortnite ]
  · players solve the spatial puzzle (fold, lattice, catalyst geometry)
  · best solutions are collected (logged as Scientific Contribution Records)
↑
[ INDUSTRIAL‑CAMEO Proxy ]
  · picks the highest‑scoring solution
  · packages it in the format CAMEO expects (e.g. PDB, CIF, JSON)
  · submits as a prediction from the corporate “AI server”
↓
[ CAMEO Private Mode ]
(returns official independent score – lDDT, RMSD, etc.)
↓
[ Smart Contract ]
  · trigger automatic payout to players proportionally to their contribution (attribution_weight)
— all without the corporation ever exposing its internal data or changing its validation workflow.
Reality: Corporations already use private CAMEO servers. INDUSTRIAL‑CAMEO proxies their requests to human solvers, then returns verified results — making qFoldIT a drop‑in R&D crowd‑sourcing layer.

Game Modes, Scoring & Attribution

Bartle types · points · attribution_weight · legal boundary

Fits: plant_growth_garden, l_systems

Fits: prospecting_survey
Human‑in‑the‑loop search Achiever
Discovery‑capable: explore pre‑vetted candidate space.
Any domain with branching candidates
Hardcore/Research Achiever, Killer
Solo or small co‑op against a threshold.
Fits: quantum_boss
Points per accepted placement (base formula)
+10 accepted placement (matches required step, or within candidate space) +0..5 speed bonus (only in team_vs_team and free‑for‑all) +5 placement that forms a new backend‑reported contact/bond -2 rejected placement attempt (does not go below 0)
This is a game score about engine‑checked events, not a new scientific metric.
attribution_weight(record) = points(record) / sum(points(r) for all records sharing the same reference_mcp_job_id AND session)
Sum = 1.0 across all participants. Mode‑aware — mode required in schema v0.2.
attribution_weight is not a royalty. It becomes royalty‑relevant only if discovery_claim.asserted is true (only via human‑in‑the‑loop after independent review) and a legal framework exists. Otherwise: recognition/leaderboard credit only.
